# Playlist API – SE4458 Assignment 2 (Group 2)

A simple REST API for a music playlist, built with **ASP.NET Core Web API (.NET 10)**, documented with **OpenAPI + Swagger UI**, and storing all data **in memory**.

- **Source code:** https://github.com/StannissDeer/SE-4458-Assigment-2-Simple-REST-API-dev-deploy
- **Live Swagger:** https://api-eight-zeta-93.vercel.app/swagger

## Endpoints

| Method | Route | Description |
|---|---|---|
| GET | `/api/songs` | List songs. Query: `search`, `genre`, `favoritesOnly`, `sortBy` (`position`, `title`, `artist`, `duration`, `genre`), `order` (`asc`/`desc`) |
| GET | `/api/songs/{id}` | Get a single song |
| GET | `/api/songs/summary` | Song count, total duration ("17 min 26 sec"), favorite count, genre breakdown |
| GET | `/api/songs/genres` | Distinct genres (for the "All Genres" filter) |
| POST | `/api/songs` | Add a song |
| PUT | `/api/songs/{id}` | Edit a song |
| DELETE | `/api/songs/{id}` | Remove a song |
| PATCH | `/api/songs/{id}/favorite` | Toggle favorite (star) |
| PATCH | `/api/songs/{id}/move` | Move a song to a new position (drag & drop) |

Example body for POST / PUT:

```json
{
  "title": "Blinding Lights",
  "artist": "The Weeknd",
  "album": "After Hours",
  "duration": "3:20",
  "genre": "Pop",
  "isFavorite": true
}
```

## Design

- **Controller → Store:** `SongsController` handles HTTP; `SongStore` is a singleton in-memory repository injected via DI (instead of a static list inside the controller), with a lock for thread safety.
- **DTOs:** `SongRequest` is used for create/update so clients cannot set `Id` or `Position`. Data annotations validate input; invalid input returns `400` automatically.
- **Duration:** stored as `DurationSeconds` (int) so sorting and total-duration math are correct; exposed as `"m:ss"` via a computed `Duration` property.
- **Ordering:** each song has a `Position`. Delete and move renumber positions so the playlist stays 1..N.
- **OpenAPI** document is generated by the built-in `Microsoft.AspNetCore.OpenApi` (`/openapi/v1.json`) and shown with `Swashbuckle.AspNetCore.SwaggerUI` at `/swagger`. XML doc comments appear as endpoint descriptions. Swagger is enabled in all environments and the root URL redirects to `/swagger`.

## Assumptions

- A single shared playlist; no users or authentication.
- Data resets whenever the app restarts (in-memory requirement). Five sample songs are seeded on startup.
- Genre is free text; filtering is case-insensitive. `genre=All` returns everything.
- Cover images are optional URLs; no file upload.

## Run locally

```bash
dotnet run
# open http://localhost:<port>/swagger
```

## Deployment (Vercel)

Deployed to Vercel as a container using `Dockerfile.vercel` and `vercel.json` (all routes are rewritten to the container service). `Program.cs` binds to `0.0.0.0` on the `PORT` environment variable (8080). A plain `Dockerfile` is also included for other hosts such as Render.

## Issues encountered

- Swagger is only enabled in Development by the default template; it had to be enabled for production.
- .NET 10 uses the built-in OpenAPI package instead of Swashbuckle, so only the Swagger UI package was added on top of it.
- Vercel routes traffic to the port in `PORT`; the app had to bind to `0.0.0.0:{PORT}`, otherwise requests fail with 502.
- A second `.csproj` in the same folder broke the build ("more than one project file"); it was removed.
- Duration stored as a string sorted incorrectly (e.g. "10:00" < "3:32"), so it was switched to seconds.
- Vercel scales the container to zero when idle and may run several instances under load. Because data is in memory, it resets after idle periods and may differ between instances (e.g. a song added on one instance may not appear on another). A shared store such as Redis would fix this, but the assignment requires an in-memory database.
